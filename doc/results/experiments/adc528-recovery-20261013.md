# 528 MHz ADC recovery investigation

## Outcome

**Twelve-bit ADC acquisition works at 528 MHz in continuous mode.** Two
60-second standalone runs each collected 70,714,285 DMA results per converter,
approximately 1.178571 MS/s per converter, at 33 MHz ADCK. DMA reported no
errors, and final-buffer codes were in 0–4095. This is a useful alternative
sampling architecture, not a qualified replacement for the current exact
1 MHz, PIT-triggered, phased, checksummed ADC-plus-GPIO stream.

The current triggered mode remains unqualified. Changing the ADC divider path,
enabling ADC_ETC B2B, selecting either ADC alone, and triggering HC0 directly
through DMA did not recover 1 MS/s at 528 MHz. The repeated ADC_ETC sweep
establishes an ongoing trigger-rate problem beyond the original boot diagnostic.
No production gate was disabled, no lower resolution was selected, and the
production default remains 450 MHz. A temporary production divider-path change
was reverted after its failed test.

## Triggered experiments

The full production image with ADICLK=0, ADIV=2 (IPG divided directly by four)
failed boot acquisition in the same way as ADICLK=1, ADIV=1 (IPG/2 divided by
two). Both produce 33 MHz. Calibration succeeded; trigger flags were `0x1c00`
and the terminal ADC_ETC error register was `0x110000`. The build passed normal
binary/memory gates, and its native ADC-register/clock tests passed 11 tests
with four unsupported combinations skipped. No sample stream was produced.

A standalone sketch then reused the production initialization and trigger
adapter while inspecting hardware status for approximately 1 ms per cell.
The 72-cell matrix varied divider path, B2B, enabled converters, and PIT period.
Software-read timing observations were also recorded. The first submission
timed out on the host and is retained as incomplete. The longer-deadline repeat
finished all 89 JSON observations; its serial output is outside the software
conversion's interrupt guard.

Representative two-converter ADC_ETC cells, normal divider and B2B disabled:

| Requested rate per ADC | 528 MHz: DONE observations per ADC | 528 MHz: error observations, both queues | 450 MHz control: error observations |
| --- | ---: | ---: | ---: |
| 500 kS/s | 499 / 498 | 0 | 0 |
| 750 kS/s | 748 / 748 | 0 | 0 |
| 857.143 kS/s | 855 / 855 | 0 | 0 |
| 923.077 kS/s | 806 / 806 | 230 | 0 |
| 960 kS/s | 599 / 599 | 719 | 0 |
| 1 MS/s | 499 / 499 | 998 | 0 |

The 450 MHz / 37.5 MHz ADCK positive control observed 998 completions per
converter at 1 MS/s with no ADC_ETC errors. Window startup and shutdown explain
why these short counts are not exactly rate multiplied by 1 ms. Error-status
observations may combine both queue bits or coalesce events; they are not an
exact lost-trigger count. Clean 1 ms cells do not qualify a sustainable rate.

The DMA-trigger alternative routes PIT through XBAR to one DMA channel writing
HC0, while another DMA channel reads ADC results. At 528 MHz it collected
499 results from 499 triggers at 500 kS/s, 462 from 923 at 923.077 kS/s,
and only one result after stopping 959 or 999 triggers at 960 kS/s or 1 MS/s.
Neither divider path helped. The reference manual states that another HC0
write during a software-triggered conversion aborts it, consistent with these
observations. At 450 MHz this alternative also failed to sustain 1 MS/s
(667/999 results with the normal divider), although the real ADC_ETC path
worked. Therefore this alternative's failure does **not** prove that the bare
ADC conversion time alone exceeds 1 us or pinpoint the failing handshake stage.

## Continuous conversion

With ADCO enabled, the ADC starts subsequent conversions internally. Single-ADC
DMA measurements at 528 MHz matched the manual's steady-state 12-bit conversion
timing for both converters and both divider paths:

| ADSTS, short sample | Steady conversion cycles | Nominal rate at 33 MHz ADCK | Results in approximately 1 ms |
| --- | ---: | ---: | ---: |
| 0 | 28 | 1.178571 MS/s | 1,178 |
| 1 | 30 | 1.1 MS/s | 1,099 |
| 2 | 32 | 1.03125 MS/s | 1,031 |
| 3 | 34 | 970.588 kS/s | 970 |

All 16 cells reported zero DMA errors and zero out-of-range codes. The two
60-second dual-ADC runs then used ADSTS=0, separate circular 16,384-word DMA
buffers, and no per-sample interrupts. Both counters were 70,714,285 in each
run, consistent with 33 MHz / 28 and the measured duration to within two samples
at the measurement boundaries. Maximum counter-poll intervals were far shorter
than a buffer wrap, making the modulo transfer accounting unambiguous.

This checks aggregate DMA progress and the final buffers, not every sample's
analog correctness or delivery. There was no external stimulus, GPIO capture,
USB sample streaming, checksum work, production ring/framing pressure, or
controlled temperature study. The two ADCs start through separate software
writes; the production 500 ns phase relationship is not established. Calibration
readiness and actual CPU/IPG clocks were checked on each fresh boot.

The current PIT clock stays crystal-derived. Continuous sampling instead follows
IPG/ADCK, itself derived from the system PLL. The shortest continuous rate is
the rational 33/28 MHz, not 1 MHz; even the slower ADSTS=2 choice is 1.03125 MHz.
Current timestamp, channel-phase, GPIO alignment and host protocol assumptions
must be redesigned and explicitly advertised before using either in a product.
No existing rate field should be relabeled as 1 MHz to hide that difference.

## Interpretation and next experiment

The [NXP RT1060 reference manual, revision 3](https://www.pjrc.com/teensy/IMXRT1060RM_rev3.pdf),
sections 66.5.4.1–66.5.4.5, distinguishes conversion initiation, aborts and
continuous conversion. Equation 1 and tables 66-4 through 66-7 give 28 ADCK
cycles for subsequent shortest-sample continuous conversions, versus 32 ADCK
plus two bus cycles for a single conversion. The latter calculation gives
984.8 ns at 33 MHz, but it is not a demonstrated external-trigger re-arm budget.
These measurements establish the useful continuous throughput and the failure
of the tested repeated-trigger paths; they do not identify every internal delay.

Section 67.3.1 describes ADC_ETC rejecting an external trigger when the previous
trigger is unfinished. Those error bits are not direct proof of an overwritten
ADC result; ADR 004's description has been corrected without changing legacy
counter names or firmware behavior. Figure 14-2 also shows the ARM/AHB/IPG
clock relationship: the tested integer-divided 528 MHz configuration does not
provide an independent 150 MHz IPG setting.

The most promising follow-up is an explicitly separate continuous-acquisition
prototype at 528 MHz, starting both ADCs with a measured phase relationship,
then adding the existing GPIO DMA, exact Adler-32 implementation, larger ADC
frames and strict loss accounting. Begin at the measured 1.03125 or 1.178571
MS/s rate, represent time rationally, and test channel/GPIO alignment and a
long combined soak. That is an architectural experiment; this report does not
approve it for integration or claim whole-system performance headroom.

## Reproduction and restoration

The [standalone sketch and instructions](adc528_probe/README.md) preserve the
successful approach and reuse the existing adapters. Both 450 and 528 MHz
versions compile against the pinned Teensy 1.62.0 core. The final 528 MHz source
was flashed and repeated the dual-ADC soak. Unlike production firmware, this
sketch has ample memory and is explicitly not a production-layout acceptance run.

The [machine-readable evidence](adc528-recovery-20261013.json) retains every
completed and incomplete hardware submission, observations, original identities
and artifact hashes. Full raw responses, firmware, per-job source snapshots when
available, and build logs remain locally under
`doc/results/raw/adc528-recovery-20261013/`. Hardware was Teensy 4.0 serial
20428100 throughout. The unrelated September analysis was not modified.

Normal-frame 450 MHz firmware `thingdaq-981ab78601d89ff7` was restored and
passed four public-SDK combined captures, eight -> sixteen -> eight -> sixteen
inputs, 20 seconds each. All four reported zero stream gaps, host queue losses
and parser corruption. An earlier restoration submission used invalid host case
names and ran no acquisition cells; that failure is retained separately. Only
the submitted SDK containers received a two-core quota; the rig service default
was unchanged. Postflight health was healthy with an empty queue.

Local validation passed both standalone clock builds, the temporary production
variant's normal build gates and 11 native tests (four unsupported combinations
skipped), and four documentation tests with 763 subtests. These checks validate
the recorded research artifacts; they do not qualify continuous mode for
production integration.
