# 528 MHz checksummed acquisition experiment

## Design

Compare the current 450 MHz CPU / 150 MHz IPG / 37.5 MHz ADC with an explicit
528 MHz CPU / 132 MHz IPG / 33 MHz ADC research selection. Both use 24 MHz
crystal-derived PIT triggers, 12-bit conversion, no averaging, standard Adler-32,
the four-generation DMA lookahead, and fixed 1 MS/s ADC-pair and GPIO rates.
The larger-frame image carries 1,012 ADC pairs per frame in sixteen-input mode.
No 10-bit fallback or independent ADACK oscillator is selected. Production
build defaults stay at 450 MHz.

The experiment extends the existing build, clock projection, and independent
wire validator. ADC initialization, INFO/STATUS clock metadata, ADC_ETC phase
(66 IPG cycles instead of 75), and DWT timing follow the selected clock. Runtime
clock readbacks and all checksum/loss acceptance rules remain strict. The
public SDK rejects the unnegotiated research clocks/layout; use the independent
validator. Clock changes alone do not increase sample rates.

Start with matched 60-second combined sixteen-input captures. A successful
528 MHz smoke permits width transitions and ten-minute endurance comparisons;
a failing smoke instead calls for bounded repetition and isolation, preserving
the failed evidence. Restore normal 450 MHz firmware at the end.

## ADC result: not qualified at 528 MHz

The 450 MHz larger-frame control passed a 60-second combined sixteen-input
capture (131 checks). At 528 MHz the first combined capture failed during
CONFIGURE: the boot ADC trigger diagnostic had already rejected acquisition.
Both ADC calibrations passed, 12-bit resolution was retained, and readback
reported 528/132/33/24 MHz CPU/IPG/ADC/PIT clocks with the expected 66-cycle phase.

Two subsequent boots reproduced that rejection: one using the same larger-frame
image after successful eight-input and sixteen-input GPIO-only cells, and one
using normal ADC frames. All three captured `adc_trigger_error_flags=7168`
(`0x1c00`: diagnostic incomplete/timeout, ADC_ETC trigger error, completion-count
mismatch) and final ADC_ETC error register `0x110000`, covering queues 0 and 4.
The timeout flag here denotes an incomplete diagnostic; it does not establish
that the full deadline elapsed. Final DONE bits were present, so zero recorded
diagnostic completions must not be interpreted as proof that no conversion
finished.

The diagnostic polls hardware status in a bounded ITCM loop with interrupts
masked; it is not a per-sample interrupt servicing benchmark. ADC DMA streaming
was never reached. Its failure was not bypassed, no lower resolution was
selected, and no ten-minute 528 MHz soak was submitted. Normal and larger ADC
frames failed alike before packet production. The narrow conversion budget
remains a concern, but this campaign does not establish the underlying cause
or prove that an isolated DMA acquisition path would necessarily fail.

These results reject the current 528 MHz / 33 MHz / 12-bit configuration as an
integration candidate. They do not demonstrate additional headroom for the
complete ADC-plus-GPIO system. The production default remains 450 MHz.

## GPIO-only comparison

The matched isolation jobs each ran eight-input GPIO-only, sixteen-input
GPIO-only, then combined sixteen-input acquisition, with 30 seconds requested
per cell. The 450 MHz job passed all three cells; the 528 MHz job passed both
GPIO cells and rejected combined acquisition before streaming.

| Case | 450 MHz GPIO packer CPU fraction | 528 MHz GPIO packer CPU fraction | Reduction |
| --- | ---: | ---: | ---: |
| Eight-input GPIO-only | 17.07% | 16.50% | 0.57 percentage points (3.3% relative) |
| Sixteen-input GPIO-only | 21.91% | 20.90% | 1.01 percentage points (4.6% relative) |
| Combined sixteen-input | 17.47% | No acquisition result | Not comparable |

These are single matched-duration observations from the packer's existing
active-cycle / elapsed-cycle telemetry. They are not total CPU measurements,
confidence intervals, or proof of a higher sustainable sample rate. Successful
cells retained 1 MS/s and passed their full checksum, continuity, loss and
conservation checks. The 17.3% faster core did not translate into a 17.3%
reduction in this measured component's CPU fraction.

## Local validation and provenance

The firmware and documentation suites passed 245 tests and 1,587 subtests.
Four deliberately unsupported fixed-rate matrix combinations were skipped.
The clock matrix alone passed 10 tests. Ruff and whitespace checks passed;
all 111 generated protocol outputs remain current. All four target builds
passed unchanged binary-layout and memory gates, retaining 34,464 bytes for
RAM1 locals/stack and 4,096 bytes for RAM2 heap.

Implementation checkpoint `b08797f` was pushed to `origin/main`. Each build's
base firmware fingerprint matches that checkpoint:
`981ab78601d89ff7b45348127817464c079927b384919609fe56a269fc4c4d88`.
Frozen manifests retain their actual pre-commit dirty-state provenance and
reproducible build timestamp; those fields have not been relabeled.

## Restoration

The final job restored normal-frame 450 MHz firmware
`thingdaq-981ab78601d89ff7` and passed the public SDK's four 20-second combined
cells, ordered eight -> sixteen -> eight -> sixteen inputs. All cells reported
zero observed gaps, queue losses, or parser corruption. Only that test job's
container CPU quota was raised from half a core to two cores; the rig service's
default allocation was unchanged. Postflight service health was healthy with
an empty queue. This is short-duration restoration validation, not an endurance
qualification. The unrelated untracked September analysis was left untouched.

## Qualification boundary

Teensy 4.0 serial 20428100, no external electrical stimulus. These checks measure
streaming integrity, not analog accuracy or input aperture. The watchdog remains
disabled. GPIO packer CPU telemetry covers that component, not total CPU
utilization. Sequential die-temperature samples do not control ambient or
starting temperature and cannot establish a thermal benefit.

## Reproduction

```bash
.venv/bin/python firmware/tools/build_input_experiment.py \
  --cpu-mhz 528 --release-fixed-1mhz --large-adc-frame
.venv/bin/python firmware/tools/run_input_isolation.py \
  --worktree "$PWD" \
  --build-dir firmware/build/input-experiment-release-large-adc-528 \
  --evidence-dir doc/results/raw/clock528-new-run \
  --case INPUT_COMBINED --profile 4 --seconds 60 --temperature \
  --frame-experiment --service http://192.168.150.14:5000
```

The [machine-readable evidence](clock528-20261013.json) retains every job,
including failures, build identities, artifact hashes, counters and temperatures.
Raw submissions, manifests, firmware, service replies, and validation logs are
retained locally under `doc/results/raw/clock528-20261013/`.
